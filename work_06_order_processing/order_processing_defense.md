Из корня проекта:

```sh

work_06_order_processing/.venv/bin/python -m pip install -r work_06_order_processing/requirements.txt
work_06_order_processing/.venv/bin/python work_06_order_processing/prepare.py
work_06_order_processing/.venv/bin/python work_06_order_processing/run.py
```

`prepare.py` сохраняет кортеж из функций и класса в `orders.bin`.
`recurse=True` включает зависимости функций, в том числе `OptionalBox`.
При прямом запуске `run.py` загружает кортеж и через `*` передаёт его
элементы в параметры функции демонстрации. Проверка `__name__ == "__main__"`
отделяет запуск сценария от импорта модуля. Импорта `prepare.py` нет.
Получателю нужны `run.py`, `orders.bin`, Python совместимой версии и `dill`
из `requirements.txt`. Локальное окружение `.venv` передавать не нужно.

Функции и методы записаны через `lambda`; нет циклов, рекурсии и отдельных
переменных с данными. `stream` — параметр для открытого файла; `self[0]`
— первый элемент неизменяемого кортежа OptionalBox. Режим `wb` записывает байты,
`rb` читает их. Повторный запуск подготовки заменяет `orders.bin`.

Двоичная сериализация не является шифрованием и не защищает от подмены.
Загружать следует только собственный или доверенный `orders.bin`: загрузка
сериализованных объектов может выполнять код. Кортеж не допускает замены
элементов на месте, но это не делает файл или вложенные объекты неизменяемыми.

Проверено: подготовка, запуск в отдельном процессе и запуск в отдельной папке
с одними `run.py` и `orders.bin`. Все четыре примера законов возвращают `True`.
На другом компьютере и другой версии Python запуск не проверялся.

## Требования и запуск

Все функции и методы записаны через `lambda`, без `def`. Нет циклов,
рекурсии, импортов и отдельных переменных с исходными или промежуточными
данными. Используются встроенные средства Python. Класс `OptionalBox`
предусмотрен заданием; `self[0]` хранит его содержимое. Параметры функций
нужны для передачи аргументов. Пользовательские функции имеют префикс
`Temeshova_`; имена класса и метода `map` взяты из задания.

Запуск из корня проекта:

```sh
python3 work_06_order_processing/order_processing.py
```

## Уровень 1. Суммы заказов

`Temeshova_order_totals` принимает последовательность заказов и возвращает
итератор `map`. Поле `total` извлекается только при запросе очередного
элемента итератора. При выводе `tuple(...)` запрашивает все элементы и
получает кортеж `(1500, 2300, 0)`. Для пустой последовательности результат
вывода — пустой кортеж `()`. Из-за дополнительного требования результат
показывается кортежем вместо указанного в исходном задании списка.

## Уровень 2. OptionalBox

`OptionalBox` наследуется от `tuple` и хранит значение либо `None`
в единственном элементе кортежа. Метод `__new__` создаёт `(value,)`.
`__slots__ = ()` запрещает добавление атрибутов экземпляра. Изменяемый
атрибут `value`, `setattr` и `__init__` больше не используются.
Элемент извлекается через `[0]`; `map` создаёт новый кортеж.
Неизменяемость контейнера не распространяется на вложенные списки и словари.

Метод `map` возвращает новый контейнер. Если значение не `None`, он применяет
переданную функцию. Иначе возвращает контейнер с `None`, не вызывая функцию.
Проверка `is not None` сохраняет возможность преобразовывать `0`, `False`
и пустую строку. Контейнер не перехватывает исключения переданной функции.

## Уровень 3. Поиск заказа

`Temeshova_find_order` отбирает заказы по `id` через `filter`.
`next(..., None)` получает первый подходящий заказ или `None`.
Последовательность заказов оборачивается в `OptionalBox`. Его метод `map` выполняет поиск
и помещает найденный словарь или `None` в новую коробку.
Через `[0]` возвращается словарь или `None`, как требует задание.
При повторяющихся `id` возвращается первый подходящий заказ.

Безопасное извлечение суммы можно записать так:

```python
OptionalBox(Temeshova_find_order((), 99)).map(lambda order: order["total"])[0]
```

Результат — `None`; обращения к полю отсутствующего заказа не происходит.

## Уровень 4. Законы функтора

Содержимое контейнеров сравнивается через `[0]`. Кортежи также
поддерживают сравнение по содержимому.

**Тождество:** `box.map(lambda x: x)` сохраняет содержимое `box`.
Для `5` обе стороны содержат `5`, для `None` — `None`.
`Temeshova_identity_law` проверяет этот закон для переданного значения.
Вызовы в `print` демонстрируют случаи с `5` и `None`.

**Композиция:** последовательные `box.map(f).map(g)` и
`box.map(lambda x: g(f(x)))` дают одинаковое содержимое.
В `Temeshova_composition_law` функция `f` прибавляет `10`, а `g` умножает
на `2`. Для `5` обе стороны дают `30`, для `None` — `None`.

Для любого непустого контейнера обе стороны вычисляют `g(f(value))`.
Для пустого обе стороны пропускают функции и сохраняют `None`.
Законы рассматриваются для чистых функций, определённых на входных значениях
и сохраняющих непустой результат при композиции: если `f` возвращает `None`,
последовательный `map` пропустит `g`, а обычная композиция вызовет `g(None)`.
Поэтому для произвольных Python-функций с таким промежуточным результатом
закон композиции не гарантирован. Демонстрационные функции этому ограничению
соответствуют. Все четыре проверки в программе должны вывести `True`.
